## 2. Launch Agent with prompt

Non-interactive invocation used by the POC adapter:

```bash
agent create-chat
agent --print --output-format json --trust --force --approve-mcps \
  --workspace C:/Users/vkita/my_code/game \
  --resume <chat_id> \
  "<exact prompt>"
```

On Windows, Python invokes the `.cmd` shim via `cmd /c` because direct
`subprocess(["agent", ...])` fails with `WinError 2`.

## 3. Terminal completion

- Process exit code `0`
- JSON line with `"subtype":"success"` when `--output-format json`
- `result` field contains the assistant text used by parsers

## 4. Full output capture

`stdout` is captured by `subprocess.run(..., capture_output=True)`.
When JSON mode is enabled, the adapter extracts the final `result` field and
also keeps the full raw stdout available for debugging.

## 6. Immediate-prior semantics for `/opsx-orch-bug-fix`

Contract requirement (R2): bare `/opsx-orch-bug-fix` consumes the **immediate
previous** Bugbot message in the same chat.

POC design therefore keeps **one chat session** for the whole loop and sends
each slash command as a separate CLI invocation with `--resume <chat_id>`.

This matches the preferred Owner flow described in the task:

```text
message #1: /review-bugbot ...
message #2: /opsx-orch-bug-fix
message #3: /review-bugbot ...
```

**Result:** `IMMEDIATE_PRIOR_BUGBOT_CONTEXT=PRESERVED` by session design.
End-to-end verification with real Bugbot + OPSX prompts was **not** executed in
this POC run because each real episode can take tens of minutes.

## 7. Third prompt in same session

Supported by repeated `--resume <chat_id>` calls in the same chat.

## 8. Subagents

The exact review prompt explicitly says to run Bugbot **without subagents**.
The adapter passes the prompt verbatim; enforcement is up to the Cursor Agent
host behavior.

## 9. Allow / confirmation prompts

Real adapter uses `--trust --force --approve-mcps` to reduce interactive gates.
Residual manual approval risk remains host-dependent.
