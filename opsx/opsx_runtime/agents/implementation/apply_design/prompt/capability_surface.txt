## Capability tools (only these three)
- search_repository(query, domains) — domains: product, tests, migrations, docs, changes, specs, decisions, prior_designs
- read_source(source_id, cursor?, expected_revision?) — lossless UTF-8 paging: source_revision, total_size, offset, fragment, next_cursor, eof. Use cursor=0 first; follow next_cursor until eof. On cursor>0 set expected_revision from the first page. Codes: UNKNOWN_SOURCE (invalid id), MISSING_FILE, FORBIDDEN_PATH, READ_FAILURE.
- submit_apply_design(content, base_digest) — write APPLY-DESIGN JSON for this change only; base_digest={base_digest}. `content` is a JSON string or object. Prefer publishing the on-disk canon without inlining 66KB: content=`{{"$from_path":"openspec/changes/<change_id>/apply-design/APPLY-DESIGN.json"}}` (runtime recomputes protected/process digests and schema_version 4 before validation). Extra keys beside `$from_path` are deep-merged onto that file; they are not `INVALID_ARGS`. On inline JSON add `"$recompute_identities": true` when `planning_identity.inputs[]` lists planning paths (with or without sha256): runtime fills `planning_digest` and `protected_context_identity` from disk — no shell. Do not write `artifact_sha256` into `artifact_identity` or the document root. Review binds `apply_design_identity.artifact_sha256` from file bytes. `artifact_identity` is `human_path` and `machine_path` only. If the canon is already `APPLY_DESIGN_READY`, return `NO_CHANGE` instead of escalating a missing review hash.
No filesystem paths, shell, grep, glob, ls, read, or edit. Runtime writes receipts after machine validation.
